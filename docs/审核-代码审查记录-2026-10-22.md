# 代码审查记录（v2.0-ai 分支，2026-10-22）

范围：Core/AI/Host 全部已生成代码（含弹性管道与虚拟网关）。基线 62 项测试全绿后逐包人工审阅。

## 发现与处置

| 编号 | 级别 | 问题 | 处置 |
|---|---|---|---|
| R1 | 🔴 资源泄漏 | `ResilientChatClient` 流式：消费方提前退出但取消令牌未触发时（上层 break 而非取消），生产者 Task 继续从模型拉 token 写入无界 Channel 直到超时——吸血鬼效应在弹性层内部的变体 | 已修：链接 CTS（消费方令牌 + 生产者生命周期），外部迭代器 `finally` 中 `CancelAsync` 终止生产者 |
| R2 | 🟡 可观测性 | `TelemetryAIFunction` 捕获全部异常回喂模型但零日志——编程缺陷（NRE 等）被静默转为模型可见文本，日志不可查 | 已修：注册器从容器解析 `ILogger` 传入，`LogError` 记录后回喂；`AddNexMesh` 补 `AddLogging()`（独立容器 NullLogger 兜底） |
| R3 | 🟡 fail-fast 缺口 | Provider 配置非法（Endpoint 非 URI / Model 为空）在第一次调用才暴露，而非启动期 | 已修：`AddNexMeshAi` 注册期校验 Model 非空 + Endpoint 合法 URI，违规直接抛 |
| R4 | 🟢 健壮性 | 多处 `asm.GetTypes()` 无 `ReflectionTypeLoadException` 防护——含动态生成类型的宿主会崩溃 | 已修：`SafeGetTypes` 跳过不可加载类型 |

## 审阅通过项（记录结论）

- **依赖方向**：AI.Approval → AI（`IToolApprovalGate` 抽象在 AI 侧，实现Approval 侧），AI 核心零审批模型引用；架构约束测试持续锁定零 FreeSql/EFCore/Redis。
- **流式语义**：首 token 守卫正确（首 token 后不重试不重复，有专项测试）；
- **上下文传播**：Enter 还原式作用域/消息头无损往返/并行隔离（20 并发×5 轮）全部有测试；
- **网关**：通配路由优先级与字面量端点共存语义正确；404/405 业务码区分；`ContainsPath` 忽略动词是 405 判定的有意设计；
- **已知取舍（不改）**：复杂 Body 缺省绑定 null 为文档化行为；弹性层流式超时是整流时长上限（可配置）；FreeSql 审批表建表用同步 `SyncStructure`（一次性，AsyncLazy 防重入）。
