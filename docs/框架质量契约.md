# 框架质量保障

> 本文档定义 NexMesh 的质量保障机制:自动化测试、依赖规则、公共 API 基线、性能基线。
> 所有机制均可在本地复现,命令见各节。

## 一、机制总览

| 机制 | 位置 | 运行命令 |
|---|---|---|
| 单元/集成测试(契约引擎、认证、AI、审批、缓存、数据层、事件总线等) | `tests/NexMesh.*.Tests` | `dotnet test` |
| 依赖规则测试 | `tests/NexMesh.ArchTests` | `dotnet test` |
| 公共 API 基线对比 | `tests/NexMesh.ArchTests/ApiBaselines` | `dotnet test`(更新基线:`NEXMESH_UPDATE_API_BASELINE=1 dotnet test`) |
| 性能基线 | `benchmarks/NexMesh.Benchmarks` | `dotnet run -c Release -- --filter *` |
| 端到端示例(SQLite 离线可跑) | `samples/NexMesh.AiDemo` | `dotnet run --project samples/NexMesh.AiDemo` |

## 二、依赖规则

包间依赖方向由测试守护(`ArchitectureIronRulesTests`),新增包时同步追加规则:

1. `NexMesh.Core` 不依赖任何兄弟包(AI/Auth/Cache/Data/Events/Host)。
2. `NexMesh.AI` 不依赖 FreeSql/EFCore/Redis 及 Data/Cache/Auth(持久化放 AI.Approval 等特性包)。
3. `NexMesh.Auth` 不依赖 AI/Events。
4. `NexMesh.Events` 不依赖 FreeSql/EFCore/Redis 及 AI/Auth/Data/Cache。
5. `NexMesh.AI.Approval` 不横向依赖 Auth/Data/Cache/Events/Host。

## 三、公共 API 基线

- 当前公共 API 面以文本形式入库(`ApiBaselines/*.txt`),与源码逐行对比。
- 任何公共 API 变更都必须显式更新基线文件并随代码一起评审。
- 生成/更新基线:`NEXMESH_UPDATE_API_BASELINE=1 dotnet test tests/NexMesh.ArchTests`。
- 破坏性变更(删除、签名变更)须在 CHANGELOG 标注并升次版本号。

### 亿级极限审计(benchmarks/NexMesh.ConcurrencyAudit 可复跑)

千万级(10M,24 核/96 并行):限流计数器与事件总线 Channel 各 10M 次交错计数**零丢失**;100 万独立 IP 分区恰好 300 万放行;慢速假 IP 内存泄漏已修复(摊销清扫,注入 134.6MB 过期后全量回收)。
百亿级(10B,24 核/96 并行,总时长 66 分钟):
- 计数器 int 溢出缺陷修复实证:21.4 亿次打击、限额 3 → 放行恰好 3(修复前 Count 溢出为负将全部放行);
- 100 亿次交错计数:放行 2,147,483,647(精确=int.MaxValue 限额)+ 拒绝 7,852,516,353(精确=余量)——零丢失零超发,判定在百亿次全程精确;吞吐 322 万 ops/s,峰值堆 3MB(全程零增长);
- 设计事实:PermitLimit 为 int,单窗口放行上限 2,147,483,647 次(约 3570 万 QPS 单 IP 才能触达,远超业务语义);
- Redis 路径:50 并发随机打散 10 万次真实网络调用,500 Key 每个恰好放行限额数(零超发零丢失,76k ops/s 含往返)。

## 五、事件总线可靠性语义(NexMesh.Events)

以下语义均有对应自动化测试(`tests/NexMesh.Events.Tests`,26 项):

| 语义 | 行为 |
|---|---|
| 有界队列 | 容量可配(`Capacity`),满则发布端回压等待;不允许无界队列 |
| 异常隔离 | 处理器异常不终止消费循环;重试耗尽进入 `IEventFaultHandler`(默认记录日志) |
| 取消语义 | 取消令牌不参与重试;停机排干阶段使用新令牌处理队列剩余事件 |
| 停机排干 | 停机后限时消费剩余事件(`DrainTimeoutSeconds`);未处理数量记入日志与 `dropped` 指标;停机后发布收到 `ChannelClosedException` |
| 正则订阅保护 | `FuzzyMatch` 正则匹配带 500ms 超时,超时按异常事件处理 |
| 执行顺序 | 订阅按"类型全名::方法名::事件 ID"排序,跨运行确定;`Unicast=true` 时仅执行首个匹配订阅 |
| 投递守恒 | 并发发布与停机叠加场景下,入队事件的结果必为"送达"或"重试耗尽"之一,无静默丢失(2000 事件混沌测试) |
| 指标 | meter `nexmesh.events`:`published` / `retried` / `dropped` / `queue_depth`(MeterListener 可订阅) |

## 六、热点路径约定

| 路径 | 约定 | 对应测试/基准 |
|---|---|---|
| 契约分发 | 启动期表达式编译强类型委托;`Task<T>` 结果与集合转换同样委托化;ref/out 参数回退反射 | DispatchBenchmarks、Core.Tests |
| 取消令牌 | `HttpContext.RequestAborted` → 契约方法 `CancellationToken` 参数 → 响应序列化 | Core.Tests |
| 时间 | `LoginRateLimiter` 等使用 `TimeProvider`(默认 `System`),时间相关行为可确定性测试 | Auth.Tests |
| 后台执行 | 事件处理经 `INexMeshBackgroundRunner`(链路接续/环境槽/独立作用域/双令牌/还原) | Events.Tests |
