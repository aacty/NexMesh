# 安全规范

NexMesh 安全体系：**默认拒绝 · 租户隔离 · AI 安全门 · 三层防御 · 信息泄露防护**。SSS+ 双轮安全审查通过。

---

## 一、默认拒绝三件套

### AutoApi 字面量模式

未标注 `[Authorize]` 或 `[AllowAnonymous]` 的端点**默认要求认证**。

```csharp
[ServiceRoute("api/employee")]
public class EmployeeService : IEmployeeBiz, IScopedService { }
// ↓ POST /api/employee/createasync → 401(未登录)
```

回退方式（仅开发）：`"NexMesh": { "AutoApi": { "AllowAnonymousByDefault": true } }`

### 虚拟网关模式

`MapAutoApiGateway` 的通配路由 handler 内执行同样的授权判定（404 优先于 401——未注册路径返回 404 而非 401）。

### 审批中心

`MapNexMeshApprovals()` 默认 `requireAuthorization: true`——四个端点（pending/detail/approve/reject）全部要求认证。

## 二、租户隔离三层闭环

### 层1：全局过滤（读路径）

```csharp
public class Order : ITenantEntity
{
    public string TenantId { get; set; } = "";
}
// → 所有 Select/Update 自动附加 WHERE TenantId = 当前租户
```

**Fail-closed 语义**：当前租户为 null 时，过滤条件为 `TenantId IS NULL`（匹配"未指定租户"行），**不是"不过滤"**。

### 层2：写入自动填充

```csharp
// Repository.FillCreate:业务不填时自动取 ICurrentUser.TenantId → TenantHelper.Current
if (entity is ITenantEntity tenantEntity && string.IsNullOrEmpty(tenantEntity.TenantId))
{
    tenantEntity.TenantId = user?.TenantId ?? TenantHelper.Current;
}
```

### 层3：缓存键隔离

语义缓存 `SearchAsync(scope, ...)` 按租户前缀匹配——A 院区的问答缓存 B 院区不可命中。

### 租户槽生命周期

```csharp
// 中间件(请求入口):作用域式绑定,Dispose 还原先前值
using (TenantHelper.Enter(snapshot.TenantId))
{
    await _next(context);
}

// BackgroundRunner(离线任务):快照租户随作用域同步还原
using var tenantScope = TenantHelper.Enter(context?.TenantId);
```

## 三、AI 安全门

### High 风险工具

| 审批门状态 | High 工具行为 |
|---|---|
| `Approval:Enabled=false`（默认） | **发现即抛异常阻断启动** |
| `Approval:Enabled=true` | 包装为挂起拦截：调用 → 入审批队列 → 返回终局文本（禁止模型编造结果） |

### 审批语义

1. **幂等键**：`SHA256(ToolName + ArgumentsJson)`——模型重复请求同一高危操作合并为同一审批单
2. **快照随队**：触发时刻的上下文（身份/租户/链路）持久化进审批单
3. **批准后执行**：经 BackgroundRunner 五步纪律，在**触发者**身份/租户下执行（不是审批人的身份）
4. **审批人不可伪造**：`DecidedBy` 一律取 `ICurrentUser.UserId`，忽略客户端传入

### 工具异常自纠错

模型参数错配（日期格式/漏必填/枚举大小写）不崩溃 Agent 循环，转为结构化错误文本回喂模型令其反思重试。回喂文本**只含异常类型名**（不泄露 SQL/连接串），详细异常仅入日志。

## 四、三层防御（AI 调用）

| 防线 | 机制 |
|---|---|
| **断连熔断** | `NexMeshCancellationGuardChatClient` 出站 LLM 调用链接 `RequestAborted`——浏览器关闭 = 模型流/函数调用/计费立即终止 |
| **上下文穿帮** | 不可变快照 + `Enter/Dispose` 还原式作用域 + AsyncLocal 并行隔离——张三 A 院的请求在并发回调中不会变成李四 B 院 |
| **弹性管道** | Polly 重试→熔断→超时；流式首 token 守卫（首 token 后不重试不重复）；消费方早退终止生产者 |

## 五、信息泄露防护

| 场景 | 防护 |
|---|---|
| 500 异常 | 返回固定文案 + TraceId，`ex.Message` 仅入日志 |
| 工具异常回喂 LLM | 只含异常类型名，不含 ex.Message |
| 生产环境 API 文档 | `MapNexMeshDocs` 默认仅开发环境；生产需显式 `force: true` |
| CORS | 未配置 Origins 时默认**拒绝跨域**（不产生 Allow-Origin 头） |
| 登录暴力破解 | per-IP 固定窗口限流（默认 5 次/60 秒），超限 429 |
| Token 时序攻击 | 256 位 CSPRNG 随机 + Ordinal 字典查找 |
| 会话内存 DoS | 惰性清扫过期/吊销会话（每 256 次操作触发） |

## 六、文件上传安全

- 表单大小上限可配置（`NexMesh:Upload:MaxSizeBytes`，默认 100MB，不再无界）
- `LocalFileStorage` 的 `id` 参数经 GUID 校验（防路径穿越 `../`）
- 生产建议：叠加文件类型白名单 + 病毒扫描钩子（业务层实现）
