# NexMesh 故障排查指南

## 日志在哪看

NexMesh 默认用 Serilog 输出 JSON 格式日志到控制台。如果你在本地跑,直接看终端输出。

```json
{"@t":"2026-10-20T12:00:00.000Z","@m":"审计 GET /api/orders → 200 耗时 5.2ms 用户:user-123 租户:tenant-001 TraceId:00-abc...","@l":"Information"}
```

在 Docker/K8s 里,日志输出到容器 stdout,用 `kubectl logs <pod>` 或日志收集器(Fluent Bit/Filebeat)拿。

想同时写文件?在 Program.cs 里加:

```csharp
builder.Host.UseSerilog((ctx, cfg) => cfg
    .WriteTo.Console()
    .WriteTo.File("logs/app-.log", rollingInterval: RollingInterval.Day));
```

## TraceId 怎么用

每个请求有一个唯一 TraceId,出现在三个地方:

1. **响应头 X-Trace-Id** → 用户报障时让他把这个头复制给你
2. **JSON 响应体 traceId 字段** → 错误响应自动带
3. **日志** → 用 TraceId 搜日志能找到这个请求的全部记录

```
用户: "接口报错了"
你:   "把响应头 X-Trace-Id 给我"
用户: "00-720c04ea-cc8ba03f-00"
你:   grep "720c04ea" app.log    ← 找到这次请求的全部日志
```

## 错误码速查

| 码 | 意思 | 常见原因 |
|---|---|---|
| 40002 | 参数校验失败 | 金额<=0、名字为空等,看 message 字段 |
| 40010 | 非法排序字段 | 前端传了不在白名单里的 sortBy |
| 40020 | 实体不支持软删除 | 实体没实现 ISoftDelete 接口 |
| 40101 | 未登录或 token 过期 | 没带 Authorization 头,或 token 过期了 |
| 40401 | 资源不存在 | 按 Id 查不到数据(或已被软删除) |
| 40901 | 重复提交 | 同一个 Idempotency-Key 并发了多个请求 |
| 40902 | 数据被别人改了 | 乐观并发冲突,前端需要刷新数据后重试 |
| 429 | 请求太频繁 | 触发限流,等一会儿再试 |
| 500 | 服务器内部错误 | 看日志(不暴露给调用方) |

## 常见坑

### 启动报 "NexMesh:Auth:Jwt:Key 未配置或长度不足"

JWT 密钥没配置,或不够 32 个字符。在 appsettings.json 或环境变量里设置:

```bash
export NexMesh__Auth__Jwt__Key="这是一个至少32个字符的密钥1234567890"
```

### 启动报 "数据源 [main] 未注册"

没调 `AddNexMeshDb`,或者数据源名称和 `IDbFactory.Get()` 传的不一致。

### 查询不到数据,但数据库里有

大概率是软删除过滤在生效。用 `repo.FindAsync(id)` 查不到已软删除的数据(这是正确行为)。

需要查已删除的数据(比如回收站功能):

```csharp
var all = await db.Get().Select<Order>()
    .DisableGlobalFilter(NexMeshDbDefaults.SoftDeleteFilterName)
    .Where(o => o.Id == id)
    .FirstAsync();
```

### 多租户看不到数据

当前租户上下文没设置。在查询前:

```csharp
using var _ = CurrentTenant.Change("tenant-001");
// 这里的查询只能看到 TenantId == "tenant-001" 的数据
```

不设置(宿主模式)能看到全部数据。

### 缓存数据不一致

写操作后记得清缓存:

```csharp
await repo.UpdateAsync(order);
await cache.Get().RemoveAsync($"order:{order.Id}");  // 别忘了清
```

### Redis 连不上

没配 Redis 连接串时自动降级到内存缓存,不影响功能。配了但连不上,前 60 秒自动降级到内存,60 秒后自动重试 Redis。

看日志里的 Warning: `Redis 连接异常,降级内存 60s`

### 开发环境 500 错误看不到详细信息

默认不暴露内部异常消息(安全考虑)。开发时开启:

```json
{ "NexMesh": { "ExposeInternalErrors": true } }
```

### 事件处理器没被调用

1. 确认注册了: `builder.Services.AddNexMeshEventHandler<OrderCreated, MyHandler>()`
2. 确认发布方在事务提交后调用(事务里发布会丢事件)
3. 看日志有没有 `[EVENT]` 相关输出

### API 文档(/scalar)打不开

生产环境默认关闭。开启:

```json
{ "NexMesh": { "Docs": { "EnableInProduction": true } } }
```

### 限流 429

默认每个 IP 60 秒最多 100 次。调大:

```json
{ "NexMesh": { "RateLimiting": { "PermitLimit": 1000, "WindowSeconds": 60 } } }
```

## /diagnostics 端点

访问 `/diagnostics` 可以看到:

- 框架版本和运行时长
- 哪些能力(包)被装配了
- 每个 API 路径的请求计数、P95 延迟、错误数

```bash
curl http://localhost:5000/diagnostics
```

这个端点运维很有用——不需要看代码就知道"这个服务启用了什么"。

## 我该用哪种 API 风格?

NexMesh 的中间件、数据层、缓存、认证在四种 API 风格下都正常工作。**FastEndpoints 和自动 API 是两种主要方式,可混用**:

| 风格 | 什么时候用 | 示例 |
|---|---|---|
| **FastEndpoints**(默认) | 中大型项目,端点类结构化,好维护 | `class CreateOrder : Endpoint<Req, Res>` |
| **自动 API**(IAutoApi) | 写接口+实现类 | `interface IOrderApi : IAutoApi` + `[HttpGet]` |
| Minimal API | 小服务、工具型 API,代码最少 | `app.MapGet(...)` |
| MVC Controller | 已有 Controller 项目迁移 | `class OrdersController : ControllerBase` |

**FastEndpoints 示例:**
```csharp
public class CreateOrder(IRepository<Order> repo)
    : Endpoint<CreateOrderRequest, ApiResult<OrderDto>>
{
    public override void Configure() { Post("/api/orders"); AllowAnonymous(); }
    public override async Task HandleAsync(CreateOrderRequest req, CancellationToken ct)
        => await HttpContext.Response.SendAsync(ApiResult<OrderDto>.Ok(dto), 201);
}
```

**自动 API 示例:**
```csharp
public interface IOrderApi : IAutoApi
{
    [HttpPost] Task<OrderDto> CreateAsync(CreateOrderRequest req);
}
public class OrderApi(IRepository<Order> repo) : IOrderApi { ... }
```

四种写法 NexMesh 中间件完全通用——MeshException 自动转 JSON、X-Trace-Id、健康检查、限流,不用改任何中间件配置。区别只在端点写法,详见 README 的"暴露 API"一节。

### /diagnostics 生产环境看不到

生产环境默认关闭(与 /scalar 同一安全基线)。开启:

```json
{ "NexMesh": { "Diagnostics": { "EnableInProduction": true } } }
```

### [EVENT] 标记

框架本身不输出 [EVENT] 标记,那是 Demo 的事件处理器自己打的日志。排查事件问题时看:
1. 事件处理器的 Error 日志(处理器抛异常时框架记 Error)
2. 自行在 handler 里加日志输出
