## 1. NexMesh.Host

**什么时候用它**:任何 NexMesh 项目的第一步——先由它把管线装好,再谈其他。

**目标**:业务项目不感知管线顺序(上下文→异常→认证→授权→契约端点→文档),一行装配。

**步骤**:

```csharp
var builder = WebApplication.CreateBuilder(args);

// ① 总装(简装模式):DI 约定/契约注册/仓储扫描/FreeSql/Kestrel 全部就位
builder.AddNexMeshService();

var app = builder.Build();

// ② 管线与端点:顺序由框架决定
app.UseNexMeshService();

app.Run();
```

模块宿主模式(需要按模块分阶段初始化或装配认证)时改用:

```csharp
builder.AddNexMeshHost(x => x.AddSecurity(s => s.AddCurrentUser<AppUserInfo>()));
// ...
app.UseNexMeshHost();
```

**验证**:启动日志输出监听地址;`GET /nexmesh/health` 返回健康检查;`/scalar` 可打开接口文档。

## 2. NexMesh.Core

**什么时候用它**:写业务接口、定义数据契约时,每时每刻都在用它的约定。

**目标**:业务只写接口与实现,路由/绑定/信封/文档由契约引擎生成。

**步骤**:

```csharp
// ① 定义契约接口(命名决定路由:IOrderApi → api/Order)
[ApiContract]
public interface IOrderApi : IServiceApi
{
    [HttpGet("page")]
    Task<PagedResult<OrderDto>> GetPageAsync(int pageIndex = 1, int pageSize = 20);

    [HttpPost("create")]
    [AllowAnonymous]                      // 显式放行;未标注默认要求认证
    Task<long> CreateAsync(CreateOrderRequest request);
}

// ② 实现类(自动 Scoped 注册,自动映射端点)
public class OrderApi(IOrderRepository repo) : IOrderApi { /* ... */ }
```

③ 无需第三步——`AddNexMeshService` 已完成扫描注册与端点映射;重复路由会在启动期报错。

**验证**:`POST /api/Order/create` 返回 `ApiResult` 信封(`success/code/data/traceId`);`GET /openapi/v1.json` 中可见字段级 schema。

## 3. NexMesh.Auth

**什么时候用它**:项目需要登录、令牌、权限校验时(几乎所有后台系统)。

**目标**:登录签发可吊销的不透明令牌,登录端点自带限流。

**步骤**:

```csharp
// ① 注册认证(默认内存会话;多实例部署加 AddNexMeshRedisAuthStore 共享会话)
builder.Services.AddNexMeshAuth(builder.Configuration);

// ② 实现登录校验(查库验密码的业务逻辑在这里)
public class DemoLoginValidator : ILoginValidator
{
    public Task<LoginUser?> ValidateAsync(string username, string password) { /* ... */ }
}
builder.Services.AddTransient<ILoginValidator, DemoLoginValidator>();

// ③ 映射端点:POST nexmesh/auth/login、logout、GET me
app.MapNexMeshAuth();
```

配置(节选):

```json
"NexMesh": {
  "Auth": { "LoginRateLimit": { "PermitLimit": 5, "WindowSeconds": 60 } },
  "Authentication": {
    "Jwt": { "AccessTokenExpirationMinutes": 1440 },
    "Redis": { "ConnectionString": "127.0.0.1:6379" }
  }
}
```

**验证**:登录成功返回 `accessToken`;超限登录返回 429 信封;带失效令牌访问受保护端点返回 401 业务码。

## 4. NexMesh.AI

**什么时候用它**:要让大模型回答业务数据相关问题,或构建对话式功能时。

**目标**:统一 Chat 管道(多 Provider/弹性/遥测/函数调用),业务方法注册为 AI 可调用工具。

**步骤**:

```csharp
// ① 注册:扫描程序集内 [NexMeshTool] 方法
builder.Services.AddNexMeshAi(builder.Configuration);

// ② 声明工具(静态或实例方法;实例方法每次调用从独立作用域解析)
public class OrderTools
{
    [NexMeshTool("根据订单号查询运单状态。低风险只读。", NexMeshRiskLevel.Low)]
    public Task<string> GetStatusAsync(string orderNo) { /* ... */ }
}

// ③ 对话端点调用工厂(Provider 可按名称切换)
var client = factory.CreateClient();          // 默认 Provider
await foreach (var update in client.GetStreamingResponseAsync(messages, options, ct))
    /* SSE 输出 */;
```

Provider 配置支持 `stub`(离线开发)与 `openai-compatible`(DeepSeek/Ollama 等)。

**验证**:`GET /api/ai/tools` 返回注册的工具清单;未配置真实 Key 时 stub Provider 也能跑通全链路。

## 5. NexMesh.AI.Approval

**什么时候用它**:AI 需要执行写操作(修改/删除/退款/通知)且不允许其自主完成时。

**目标**:高危写操作不直达业务——AI 调用时挂起入队,人工批准后按快照执行。

**步骤**:

```csharp
// ① 声明高危工具
[NexMeshTool("对指定订单执行强制关闭。高危写操作!", NexMeshRiskLevel.High)]
public Task CloseOrderAsync(long orderNo) { /* ... */ }

// ② 开启审批门(队列走 FreeSql 持久化)
builder.Services.AddNexMeshApproval(builder.Configuration);   // Store=FreeSql
// ③ 审批中心端点(全部要求认证)
app.MapNexMeshApprovals(requireAuthorization: true);
```

**验证**:AI 触发关闭订单时模型收到"已挂起,审批单号 xxx";`GET nexmesh/approvals/pending` 可见待审单;批准后订单真正关闭,拒绝则永不执行。同参数重复请求合并为同一审批单(幂等键)。

## 6. NexMesh.AI.Workflow

**什么时候用它**:一个业务动作要分多步完成,且中间需要等人工或等外部系统时。

**目标**:多步骤流程带检查点,可挂起(等人工/等外部)后从断点恢复。

**步骤**:

```csharp
// ① 定义步骤
public class CollectMaterials : NexMeshWorkflowStep
{
    public override Task<StepStatus> ExecuteAsync(StepContext context) { /* ... */ }
}
public class DirectorReview : NexMeshWorkflowStep
{
    // 返回 Suspended 即挂起落检查点
    public override Task<StepStatus> ExecuteAsync(StepContext context) { /* ... */ }
}

// ② 注册(检查点默认内存,配 FreeSql 后持久化)
builder.Services.AddNexMeshWorkflow(builder.Configuration);

// ③ 启动与恢复
var checkpoint = await engine.StartAsync("order-review", steps, context: null, ct);
// 人工审核完成后:
await engine.ResumeAsync(workflowId, steps, ct);
```

**验证**:`ListSuspendedAsync()` 可列出挂起中的流程;恢复后从挂起步骤继续,已完成步骤不重跑;`RecoverStaleAsync` 可接管异常中断的 Running 流程。

## 8. NexMesh.Events

**什么时候用它**:一个动作发生后要触发多个后续处理(通知/统计/联动),且不想让调用方等它们完成时。

**目标**:进程内解耦——发布方与处理方互不感知,队列有界、停机可排干。

**步骤**:

```csharp
// ① 注册(自动扫描程序集内 IEventSubscriber 实现)
builder.Services.AddNexMeshEvents(builder.Configuration);

// ② 订阅(方法签名:Task Xx(EventContext);可叠加多个特性)
public class OrderSubscriber : IEventSubscriber
{
    [EventSubscribe("order:created", NumRetries = 3, RetryTimeoutMs = 200)]
    [EventSubscribe(@"^order:\d+:paid$", FuzzyMatch = true)]
    public Task OnOrder(EventContext context)
    {
        var order = context.GetPayload<OrderCreated>();
        // context.Context 携带发布时刻的用户/租户快照
        return Task.CompletedTask;
    }
}

// ③ 发布(注入 IEventPublisher;队列满时回压等待,不丢事件)
await publisher.PublishAsync("order:created", new OrderCreated { OrderId = 42 });
```

可靠性语义(均有对应自动化测试):

| 语义 | 行为 |
|---|---|
| 有界队列 | 容量可配,满则发布端等待;永不无界 |
| 异常隔离 | 处理器抛异常不影响总线运行;重试耗尽进入 IEventFaultHandler |
| 取消 | 取消信号不参与重试;停机排干阶段使用新令牌处理队列剩余事件 |
| 停机 | 限时排干,剩余事件计数记日志与 `dropped` 指标;停机后发布收到明确异常 |
| 顺序 | 订阅执行顺序确定(类型全名::方法名::事件ID 排序);`Unicast` 配置可改为单订阅执行 |
| 指标 | meter `nexmesh.events`:`published` / `retried` / `dropped` / `queue_depth` |

**验证**:`tests/NexMesh.Events.Tests` 覆盖上述全部语义(含两万次事件并发投递守恒测试)。

## 9. NexMesh.Cache

**什么时候用它**:读多写少的数据想加速;或同一接口要防重复提交时。

**目标**:本地+分布式双层缓存与接口幂等。

**步骤**:

```csharp
// ① 注册(数据源在 NexMesh:Cache:Sources 配置;Mode=Memory 强制全本地)
// "NexMesh": { "Cache": { "Mode": "Redis", "Sources": { "main": { "ConnectionString": "127.0.0.1:6379" } } } }

// ② 使用(注入 ICacheFactory,按名取源)
var cache = cacheFactory.Get("main");
await cache.SetStringAsync("key", value, TimeSpan.FromMinutes(5));
builder.Services.AddNexMeshCache(builder.Configuration);

// ③ 接口幂等(重复请求命中缓存直接返回首次结果)
app.UseNexMeshIdempotency();
```

**验证**:同一幂等键的重复请求返回同一结果;缓存击穿场景(热 key 过期瞬间并发)仅回源一次。

## 13. NexMesh.Data.Migrations

**什么时候用它**:生产环境的表结构变更要可评审、可回滚、可审计——替代开发期 AutoSyncStructure。

**步骤**:

```csharp
// ① 定义迁移(Version 升序;UpAsync 内写 DDL/数据变更,SQL 按目标库方言写)
public class V202610250001_CreateOrders : NexMeshMigration
{
    public override long Version => 202610250001;
    public override string Name => "创建订单表";
    public override Task UpAsync(IFreeSql db, CancellationToken ct = default)
        => Task.FromResult(db.Ado.ExecuteNonQuery(
            "CREATE TABLE orders (id BIGINT PRIMARY KEY, note VARCHAR(256) NOT NULL)"));

    public override Task DownAsync(IFreeSql db, CancellationToken ct = default)   // 可选:回滚
        => Task.FromResult(db.Ado.ExecuteNonQuery("DROP TABLE orders"));
}

// ② 注册(扫描程序集;第二个库的迁移用 override Source)
builder.Services.AddNexMeshMigrations(builder.Configuration, typeof(V202610250001_CreateOrders).Assembly);

// ③ 执行:显式(推荐,可控制与种子顺序;在 Build 与 UseNexMeshHost 之间)
await app.MigrateNexMeshAsync();
//   或配置 NexMesh:Migrations:Enabled=true 由宿主启动自动执行
```

**语义**:升序应用、单迁移单事务(失败回滚当条并阻止启动)、已应用跳过;**同版本重复 → 启动报错;已发布迁移被改动(Checksum)→ 启动报错**;多库按 Source 各自独立。记录表 nexmesh_migration 自动创建。

**验证**:`tests/NexMesh.Data.Migrations.Tests` 覆盖顺序/幂等/回滚/校验/多源/回退全部语义。

## 14. OIDC 外部 IdP 对接(Auth)

**什么时候用它**:企业有统一身份中心(Keycloak/AD/企业 SSO),NexMesh 服务要接受其签发的令牌登录。

**步骤**:

```csharp
// ① 配置(验证方式二选一:HS256 对称密钥 / RS256 公钥)
// "NexMesh": { "Authentication": { "Oidc": {
//     "Issuer": "https://sso.corp", "Audience": "myapp",
//     "RsaPublicKeyPem": "-----BEGIN PUBLIC KEY-----
..." } } }

builder.Services.AddNexMeshAuth(builder.Configuration); // 无需其他注册

// ② 前端拿到 IdP 的 JWT 后调登录端点换发本地令牌(token-exchange)
//    POST /nexmesh/auth/login  {"oidcToken":"<IdP JWT>"}
//    → {"data":{"accessToken":"本地令牌",...}} 之后的用法与普通登录完全一致
```

**语义**:验证通过换发本地不透明令牌——滑动续期/登出吊销/ICurrentUser 全部保留;JWT 无效/过期/iss-aud 不符/签名错误 → 401。验证器为自研轻实现(HS256/RS256,零外部依赖)。

**验证**:`tests/NexMesh.Auth.Tests`(验证器 6 项:自造 RS256/HS256 覆盖有效/篡改/过期/无 exp;JWKS 在线发现闭环;自建 IdP↔RP 端到端 3 项见第 18 节)。

## 15. 契约 gRPC 面(Host)

**什么时候用它**:内部服务间高频调用想要 HTTP/2 长连接与二进制传输,又不想为每个契约维护 .proto。

**步骤**:

```csharp
// ① 注册(业务契约零生成——通用网关按 (service, method) 路由)
builder.Services.AddNexMeshGrpc(typeof(IOrderApi).Assembly);
// ② 端点(app 阶段,与 MapNexMeshContracts 并列;模块宿主装配时 UseNexMeshHost 自动挂)
app.MapNexMeshGrpc();
// ③ 可选:NexMesh:GrpcPort=50011 → Kestrel 自动追加 Http2 监听(模块宿主)
```

调用方(引 NexMesh.Host 包即得生成好的 client):

```csharp
var client = new NexMesh.Grpc.ContractGateway.ContractGatewayClient(channel);
var reply = await client.InvokeAsync(new NexMesh.Grpc.ContractCall
{
    Service = "order",          // 契约服务名(与 REST 路由段一致)
    Method  = "Search",         // 方法名去 Async
    ArgsJson = """{"keyWords":"abc","pageIndex":1}""",
});
// reply.EnvelopeJson = REST 同款 ApiResult 信封
```

**验证**:`tests/NexMesh.Host.Tests` 双面一致测试(同一契约 REST 与 gRPC 返回同一信封)。

## 16. NexMesh Dashboard(框架管理台,并入 Host)

**什么时候用它**:想用浏览器看框架运行状态(环境/端点/模块/AI 工具/待审单/后台作业/事件队列),并对高危 AI 操作做人工批准。

**步骤**:

```csharp
app.MapNexMeshDashboard();           // 开发环境默认可用
app.MapNexMeshDashboard(force: true); // 生产显式开启
```

## 18. 自建 OIDC IdP(当身份中心,Auth)

**什么时候用它**:你的 NexMesh 服务就是身份中心,别的系统(或另一个 NexMesh 服务)要拿它登录——授权码 + PKCE、client_credentials、发现文档、JWKS 全齐,零外部依赖。配合第 14 节,框架自己同时跑通"发令牌"和"收令牌"两端。

**步骤**:

```csharp
// ① 注册 IdP(生产把内存存储换成数据库实现)
var users = new InMemoryUserStore();
users.Add(new OidcIdpUser("u1", "张三", "tenant-x", ["manager"]));
var clients = new InMemoryClientStore();
clients.Add(new OidcClient { ClientId = "rp-app", RedirectUris = ["https://app.mycorp/cb"] });

builder.Services.AddNexMeshOidcIdp(o =>
{
    o.Issuer = "https://sso.mycorp";   // 与 RP 侧 OidcOptions.Issuer 填同一个
});
builder.Services.AddSingleton<IOidcUserStore>(users);    // 覆盖默认内存实现(同上语义,可换数据库实现)
builder.Services.AddSingleton<IOidcClientStore>(clients);

// ② 挂端点:发现文档与 JWKS 按 OIDC 惯例在根路径,authorize/token 在 /oidc
app.MapNexMeshOidcIdp(); // 默认前缀 /oidc

// ③ 对接方(RP)用同一框架接收(闭环):
//    var keys = await OidcJwksFetcher.FetchAsync("https://sso.mycorp");
//    validator.SetJwksKeys(keys);           // 轮换 = 重新拉取后原子替换
//    var user = validator.Validate(idpJwt); // → LoginUser(sub/UserName/TenantId/ClaimList)
//    POST /nexmesh/auth/login {"oidcToken": idpJwt} → 换发本地不透明令牌
```

**语义**:

- authorize 要求 PKCE S256(标准 base64url challenge);客户端与 redirect_uri 需注册;一次性授权码 90 秒过期。
- token 支持 authorization_code(一次性消费 + PKCE 验证,兑换后查用户存储签发完整声明)与 client_credentials(注册密钥校验)。
- 签发 JWT 为 RS256 + `kid` 标头;声明 sub/preferred_username/tenantid/roles 与 RP 验证器映射一一对应;`RotateKey()` 轮换后 /jwks 自动吐新 kid。
- 不做:implicit(已废弃)、刷新令牌滚动、client secret JWT 签名(留扩展点)。

**验证**:`tests/NexMesh.Auth.Tests` 3 项闭环(授权码 PKCE 全流程——JWKS 发现→验签→token-exchange 换发本地令牌;授权码一次性+PKCE 错拒;client_credentials 错凭据 401)。
