## 方式一:本地开发

最简单,直接跑:

```bash
cd MyApp
dotnet run
# 默认 http://localhost:5000
# 调试 UI: http://localhost:5000/scalar
```

不需要装 Redis/RabbitMQ/数据库(框架自动降级到内存/SQLite)。

## 方式二:Windows 服务

把 NexMesh 服务注册为 Windows 服务,开机自启,崩溃自动重启。

### 第一步:发布

```powershell
dotnet publish -c Release -o C:\Apps\MyApp --self-contained false
```

### 第二步:创建 Windows 服务

以管理员身份运行 PowerShell:

```powershell
# 创建服务
sc.exe create "MyApp.OrderService" `
    binPath= "C:\Apps\MyApp\MyApp.OrderService.exe" `
    start= auto `
    DisplayName= "订单服务" `
    Description= "NexMesh 订单管理系统"

# 设置崩溃自动重启
sc.exe failure "MyApp.OrderService" reset= 86400 actions= restart/5000/restart/10000/restart/60000

# 启动服务
sc.exe start "MyApp.OrderService"

# 查看状态
sc.exe query "MyApp.OrderService"
```

### 第三步:配置环境变量

```powershell
# 系统级环境变量(服务启动时读取)
[Environment]::SetEnvironmentVariable("ConnectionStrings__Main", "Server=...;Database=...", "Machine")
[Environment]::SetEnvironmentVariable("NexMesh__Auth__Jwt__Key", "生产密钥至少32字符...", "Machine")

# 重启服务生效
sc.exe stop "MyApp.OrderService"
sc.exe start "MyApp.OrderService"
```

### 常用命令

```powershell
sc.exe stop "MyApp.OrderService"       # 停止
sc.exe start "MyApp.OrderService"      # 启动
sc.exe delete "MyApp.OrderService"     # 删除
Get-EventLog -LogName Application -Source "MyApp.OrderService" -Newest 20   # 查看日志
```

### 环境变量方式(替代 appsettings)

也可以在项目里创建 `appsettings.Production.json`:

```json
{
  "ConnectionStrings": {
    "Main": "Server=prod-db;Database=orders;Uid=...;Pwd=..."
  },
  "NexMesh": {
    "Auth": { "Jwt": { "Key": "生产密钥..." } }
  }
}
```

然后设置环境变量 `ASPNETCORE_ENVIRONMENT=Production`。

## 方式三:IIS 部署

### 前置条件

1. Windows Server + IIS 10+
2. 安装 [.NET Hosting Bundle](https://dotnet.microsoft.com/download/dotnet/10.0)(包含 ASP.NET Core Module)

```powershell
# 用 Chocolateau 安装:
choco install dotnet-aspnetruntime -y
# 或手动下载 Hosting Bundle 安装
```

### 第一步:发布

```powershell
dotnet publish -c Release -o C:\publish\MyApp
```

### 第二步:IIS 创建站点

1. 打开 IIS 管理器
2. 右键"网站" → "添加网站"
3. 网站名称: `MyApp`
4. 物理路径: `C:\publish\MyApp`
5. 端口: `8080`(或 80)
6. 点击确定

### 第三步:设置应用程序池

1. 打开"应用程序池"
2. 找到刚创建的 `MyApp` 池
3. 右键 → "基本设置"
4. .NET CLR 版本: **无托管代码**(重要!不是 v4.0)
5. 标识: 按需(默认 ApplicationPoolIdentity 即可)

### 第四步:权限

```powershell
# 给 IIS 应用池用户读权限
icacls "C:\publish\MyApp" /grant "IIS AppPool\MyApp:(OI)(CI)R" /T
```

### web.config(IIS 需要)

发布时自动生成,如果需要自定义:

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <system.webServer>
    <handlers>
      <add name="aspNetCore" path="*" verb="*" modules="AspNetCoreModuleV2" resourceType="Unspecified" />
    </handlers>
    <aspNetCore processPath="dotnet"
                arguments=".\MyApp.dll"
                stdoutLogEnabled="true"
                stdoutLogFile=".\logs\stdout"
                hostingModel="inprocess">
      <environmentVariables>
        <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" />
        <environmentVariable name="ConnectionStrings__Main" value="Server=...;Database=..." />
        <environmentVariable name="NexMesh__Auth__Jwt__Key" value="生产密钥..." />
      </environmentVariables>
    </aspNetCore>
  </system.webServer>
</configuration>
```

### 常见 IIS 问题

| 问题 | 解决 |
|---|---|
| 500.30 进程启动失败 | 检查 .NET Hosting Bundle 是否安装 |
| 500.31 加载 ANCM 失败 | 应用程序池 .NET CLR 版本改为"无托管代码" |
| 500.35 多进程不允许 | hostingModel 改为 "outofprocess" |
| 日志在哪 | `C:\publish\MyApp\logs\` 或 IIS 日志 |

## 方式四:Linux systemd 服务

### 第一步:发布

```bash
dotnet publish -c Release -o /opt/myapp
```

### 第二步:创建服务文件

```bash
sudo tee /etc/systemd/system/myapp.service << 'EOF'
[Unit]
Description=NexMesh Order Service
After=network.target

[Service]
Type=exec
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/dotnet /opt/myapp/MyApp.dll
Restart=always
RestartSec=5
KillSignal=SIGINT
SyslogIdentifier=myapp
User=www-data
Environment=ASPNETCORE_ENVIRONMENT=Production
Environment=ASPNETCORE_URLS=http://*:8080
Environment=ConnectionStrings__Main=Server=...;Database=...
Environment=NexMesh__Auth__Jwt__Key=生产密钥...

[Install]
WantedBy=multi-user.target
EOF
```

### 第三步:启动

```bash
sudo systemctl daemon-reload
sudo systemctl enable myapp       # 开机自启
sudo systemctl start myapp        # 启动
sudo systemctl status myapp       # 查看状态
```

### 常用命令

```bash
sudo systemctl stop myapp          # 停止
sudo systemctl restart myapp       # 重启
journalctl -u myapp -f             # 实时查看日志
journalctl -u myapp --since today  # 今天的日志
```

## 方式五:Docker 容器

### Dockerfile

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app

FROM mcr.microsoft.com/dotnet/aspnet:10.0
WORKDIR /app
COPY --from=build /app ./
ENV ASPNETCORE_URLS=http://+:8080
EXPOSE 8080
ENTRYPOINT ["dotnet", "MyApp.dll"]
```

### 构建和运行

```bash
# 构建
docker build -t myapp:1.0.0 .

# 运行
docker run -d \
  --name myapp \
  -p 8080:8080 \
  -e ConnectionStrings__Main="Server=...;Database=..." \
  -e NexMesh__Auth__Jwt__Key="生产密钥..." \
  --restart unless-stopped \
  myapp:1.0.0

# 查看日志
docker logs -f myapp
```

### docker-compose(完整开发环境)

```yaml
version: '3.8'
services:
  app:
    build: .
    ports: [ "8080:8080" ]
    environment:
      - ConnectionStrings__Main=Server=mysql;Database=orders;Uid=root;Pwd=root123
      - NexMesh__Auth__Jwt__Key=production-secret-key-at-least-32-chars
      - NexMesh__Cache__Sources__main__ConnectionString=redis:6379
    depends_on: [ mysql, redis ]

  mysql:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: root123
      MYSQL_DATABASE: orders
    ports: [ "3306:3306" ]

  redis:
    image: redis:7-alpine
    ports: [ "6379:6379" ]
```

## 方式六:Kubernetes

### Deployment + Service

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
  labels: { app: myapp }
spec:
  replicas: 3
  selector:
    matchLabels: { app: myapp }
  template:
    metadata:
      labels: { app: myapp }
    spec:
      containers:
        - name: myapp
          image: myregistry/myapp:1.0.0
          ports: [ { containerPort: 8080 } ]
          env:
            - name: ASPNETCORE_ENVIRONMENT
              value: Production
            - name: ConnectionStrings__Main
              valueFrom: { secretKeyRef: { name: myapp-secrets, key: db-connection } }
            - name: NexMesh__Auth__Jwt__Key
              valueFrom: { secretKeyRef: { name: myapp-secrets, key: jwt-key } }
          livenessProbe:
            httpGet: { path: /health/live, port: 8080 }
            initialDelaySeconds: 10
            periodSeconds: 30
          readinessProbe:
            httpGet: { path: /health/ready, port: 8080 }
            initialDelaySeconds: 5
            periodSeconds: 10
          resources:
            requests: { cpu: 250m, memory: 256Mi }
            limits: { cpu: 1000m, memory: 512Mi }
---
apiVersion: v1
kind: Service
metadata:
  name: myapp
spec:
  selector: { app: myapp }
  ports: [ { port: 80, targetPort: 8080 } ]
  type: ClusterIP
---
apiVersion: v1
kind: Secret
metadata:
  name: myapp-secrets
type: Opaque
stringData:
  db-connection: "Server=...;Database=..."
  jwt-key: "生产密钥至少32字符..."
```

### 创建

```bash
kubectl apply -f myapp-deployment.yaml
kubectl get pods -l app=myapp
kubectl logs -f deployment/myapp
```

## 发布命令

### 标准 Release

```bash
dotnet publish -c Release -o ./publish
```

### 自包含(目标机器不需要装 .NET)

```bash
dotnet publish -c Release -r win-x64 --self-contained true -o ./publish/win
dotnet publish -c Release -r linux-x64 --self-contained true -o ./publish/linux
```

### 单文件(所有 DLL 打成一个 exe)

```bash
dotnet publish -c Release -r win-x64 \
    --self-contained true \
    -p:PublishSingleFile=true \
    -p:IncludeNativeLibrariesForSelfExtract=true \
    -o ./publish/single
# 生成一个 MyApp.exe,拷到目标机器直接跑
```

### AOT(启动最快,体积最小)

```bash
dotnet publish -c Release -r linux-x64 -p:PublishAot=true -o ./publish/aot
```

### Trim(裁剪不用的代码,减小体积)

```bash
dotnet publish -c Release --self-contained true -p:PublishTrimmed=true -o ./publish/trimmed
```

## 单文件发布

生成的可执行文件包含所有依赖(不需要目标机器安装 .NET):

```bash
dotnet publish -c Release -r win-x64 \
    --self-contained true \
    -p:PublishSingleFile=true \
    -o ./publish

# 生成:
# publish/
# ├── MyApp.exe          ← 唯一的可执行文件(约 80MB,含运行时)
# └── appsettings.json   ← 配置文件(不打入 exe,方便修改)

# 部署:把 publish/ 目录拷到目标机器,双击 MyApp.exe 或注册为服务
```

## 配置清单

| 变量 | 必填 | 说明 |
|---|---|---|
| `ASPNETCORE_ENVIRONMENT` | 建议设 | `Development` / `Staging` / `Production` |
| `ASPNETCORE_URLS` | 可选 | 监听地址,默认 `http://localhost:5000` |
| `ConnectionStrings__Main` | 是(接数据库) | 主库连接串 |
| `ConnectionStrings__Slave` | 可选 | 从库连接串(读分离) |
| `NexMesh__Auth__Jwt__Key` | **生产必换** | HS256 密钥,≥32 字符 |
| `NexMesh__Auth__ApiKeys__0` | 服务间调用时 | X-Api-Key 合法键 |
| `NexMesh__Cache__Sources__main__ConnectionString` | 可选 | Redis 地址(不配自动用内存) |
| `NexMesh__Events__Transport` | 可选 | `Memory`(默认)/ `RabbitMQ` |
| `NexMesh__Observability__EnableOpenTelemetry` | 可选 | 开启 Traces/Metrics |
| `NexMesh__Observability__OtlpEndpoint` | 可选 | OTLP Collector 地址 |
| `NexMesh__RateLimiting__PermitLimit` | 可选 | 每窗口最大请求数(默认 100) |
| `NexMesh__RateLimiting__WindowSeconds` | 可选 | 窗口秒数(默认 60) |
| `NexMesh__Diagnostics__EnableInProduction` | 可选 | 生产开启 /diagnostics(默认关) |
| `NexMesh__Docs__EnableInProduction` | 可选 | 生产开启 /scalar(默认关) |

**环境变量优先级 > appsettings.{Env}.json > appsettings.json**

未配置 Redis/RabbitMQ 时框架自动内存降级/进程内直派。

## K8s 探针

NexMesh 自动提供三个端点:

| K8s 探针 | 端点 | 说明 |
|---|---|---|
| livenessProbe | `/health/live` | 进程存活(数据库挂了不影响) |
| readinessProbe | `/health/ready` | 依赖就绪(数据库挂了 503) |
| 启动探针 | `/health` | 建议同 liveness |

```yaml
livenessProbe:
  httpGet: { path: /health/live, port: 8080 }
  initialDelaySeconds: 10
readinessProbe:
  httpGet: { path: /health/ready, port: 8080 }
  initialDelaySeconds: 5
```

## 优雅关闭

- ASP.NET Core 默认处理 SIGTERM/CTRL+C:停止接收新请求,等待在途请求完成
- 默认超时 5 秒,可通过 `ShutdownTimeout` 调整
- K8s: `terminationGracePeriodSeconds: 30`
- 后台任务: `NexMeshPeriodicWorker` 自动优雅退出
- CAP 消费: 通过 `IHostApplicationLifetime.ApplicationStopping` 订阅

## 选择建议

| 场景 | 推荐方式 |
|---|---|
| 本地开发 | dotnet run |
| 单台 Windows 服务器 | Windows 服务(开机自启 + 崩溃重启) |
| 已有 IIS 基础设施 | IIS 部署 |
| 单台 Linux 服务器 | systemd 服务 |
| 容器化环境 | Docker |
| 大规模微服务 | Kubernetes |
| 客户内网(无法装运行时) | 单文件发布 + Windows 服务 |
