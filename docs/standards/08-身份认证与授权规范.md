# 08 身份认证与授权规范

## 方案选择

| 场景 | 方案 |
|---|---|
| 用户(前端/App) | JWT(`AddNexMeshJwt`) |
| 服务间调用 | ApiKey(`AddNexMeshApiKey`,X-Api-Key 头) |
| 开放给第三方 | JWT + 限流(`AddNexMeshRateLimiter`)+ 独立 Audience |

## 密钥管理

- **[强制]** HS256 Key ≥ 32 字符,生产从环境变量/密钥库注入:`NexMesh__Auth__Jwt__Key`;**[禁止]** 入库、入仓、入日志
- **[强制]** ApiKey 每个调用方独立一把,泄露单点吊销;恒定时间比较由框架保证,禁止自己 == 比较
- **[建议]** Key 轮换:新旧双 Key 并行一周(校验接受两者,签发只用新)

## Token 纪律

- **[强制]** claim 只放授权必需项(`sub`/`name`/`role`),**[禁止]** 塞手机号/权限明细等敏感或大对象
- **[强制]** 有效期 ≤ 120 分钟;刷新走新 token,禁止长效 token
- **[强制]** 签发入口(登录)必须先验密码再做限流防爆破(`NexMesh:RateLimiting` 收紧该路由)

## 端点保护

- **[强制]** 默认拒绝:端点显式 `AllowAnonymous()` 才匿名,其余一律认证(FastEndpoints 反转默认,写端点时注意)
- **[强制]** 授权到角色/策略:`Roles("admin")` 或策略;资源级(只能删自己的单)在端点内比对 `ICurrentUser.Id`,比对失败抛 403(40301)
- **[建议]** 用户身份一律经 `ICurrentUser` 注入获取,**[禁止]** 自己解析 `HttpContext.User` claims
