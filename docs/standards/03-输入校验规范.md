# 03 输入校验规范

## 两层校验,边界清晰

| 层 | 工具 | 职责 | 失败响应 |
|---|---|---|---|
| 格式校验 | FluentValidation(随 FastEndpoints) | 类型/长度/范围/格式,与上下文无关 | 框架 400(字段级 errors) |
| 业务校验 | `MeshException` | 需要查库/查上下文的规则 | `ApiResult.Fail(业务码, 消息)` |

## 规则

- **[强制]** 格式规则进 Validator,一行一条,消息可读:

```csharp
public sealed class CreateOrderValidator : Validator<CreateOrderRequest>
{
    public CreateOrderValidator()
    {
        RuleFor(x => x.CustomerName).NotEmpty().MaximumLength(50);
        RuleFor(x => x.Amount).GreaterThan(0);
    }
}
```

- **[强制]** 业务规则在端点/Service 里抛 `MeshException`,带专用错误码:

```csharp
if (await repo.ExistsAsync(o => o.CustomerName == req.CustomerName))
    throw new MeshException("客户存在未完成订单,禁止重复下单", errorCode: 40901);
```

- **[禁止]** 把业务规则塞进 Validator(Validator 里查库 = 隐藏的 N 次查询)
- **[禁止]** 手写 `if (!ModelState.IsValid)` 之类的散落检查——框架已接线,别重复
- **[建议]** 错误消息面向调用方(可展示),不夹带实现细节("金额必须大于 0" ✓,"decimal parse failed at line 3" ✗)
- **[建议]** 同一规则在多个端点出现时,抽到共享 Validator 或领域方法,别复制
