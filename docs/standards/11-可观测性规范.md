# 11 可观测性规范

## 日志

- **[强制]** 结构化模板 + 命名占位,禁止字符串插值拼日志:

```csharp
logger.LogInformation("订单 {OrderId} 已创建,金额 {Amount}", order.Id, order.Amount);  // ✓
logger.LogInformation($"订单 {order.Id} 已创建");                                      // ✗
```

- **[强制]** 级别语义:Trace/Debug=排查细节(生产默认关)、Information=业务里程碑、Warning=可自动恢复的异常(缓存降级/限流触发)、Error=需要人工介入(未知异常框架已带堆栈)
- **[禁止]** `Console.WriteLine`/`Debug.WriteLine` 进主干
- **[强制]** 日志里的敏感字段先脱敏:`NexMask.Phone(mobile)`;完整身份证/密码/token **永不**入日志

## TraceId 贯穿(框架保证,别破坏)

同一请求三处同源:响应头 `X-Trace-Id`、`ApiResult.TraceId`、日志事件。排障流程:用户报 TraceId → 日志检索 → 关联链路。

- **[禁止]** 自己生成/覆盖 TraceId;客户端可用响应头回传做二次关联

## 指标与链路

- **[强制]** `EnableOpenTelemetry` 生产开启,`OtlpEndpoint` 指向 Collector;采样从 0.1 起按流量调
- **[建议]** 关键业务在 Service 层记自定义指标(次数/耗时),不必给每个函数都加 span
- **[建议]** 告警起步集:5xx 率、P95 延迟、限流触发数、Redis 降级次数(Warning 日志)

## 排障入口

```
/scalar 调试复现 → TraceId 查日志 → OTel 看调用链 → /health/ready 看依赖状态
```
