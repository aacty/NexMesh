# 06 事务与一致性规范

## 本地事务(单库)

- **[强制]** 多写操作使用 FreeSql UnitOfWork(与数据源同连接,支持异步仓储调用):

```csharp
// 经 IDbFactory 取 IFreeSql;uow 内的写操作要么全部提交要么全部回滚
var fsql = db.Get();
using var uow = fsql.CreateUnitOfWork();
try
{
    var orderRepo = uow.GetRepository<OrderEntity>();
    var stockRepo = uow.GetRepository<StockEntity>();
    await orderRepo.InsertAsync(order);
    await stockRepo.UpdateAsync(stock);
    uow.Commit();
}
catch
{
    uow.Rollback();
    throw;
}
```

- **[强制]** 删除一律软删除(`SoftDeleteAsync`);物理删除仅限合规/归档场景且 PR 里注明审批依据
- **[禁止]** 事务里做远程调用(HTTP/gRPC/发邮件)——锁持有时间不可控;远程动作移到事务提交后
- **[注意]** `fsql.Ado.Transaction(Action)` 是线程绑定同步 API,**不能**包裹含 `await` 的仓储调用(续体线程不参与事务);异步场景一律用上面的 UnitOfWork

## 跨服务(最终一致)

- **[强制]** 跨服务不用分布式事务/2PC;用**事件 + 幂等消费**:

```
本地事务提交 → events.PublishAsync(OrderCreated) → 订阅方处理失败可重试
```

- **[强制]** Memory 总线只用于**单服务内**解耦;跨服务必须 `Transport=RabbitMQ`(CAP Outbox:业务库与消息表同库同事务,崩溃不丢)
- **[强制]** 消费端幂等:以事件 Id 或业务键去重(如 `TryAdd` 标记表),重复投递不得产生双写
- **[建议]** 长链路(>3 服务)考虑 Saga:正向事件 + 补偿事件,每个补偿自身也幂等

## 分布式锁

- **[强制]** 跨实例互斥用 `ICacheSource.TryLockAsync`(Redis 模式:SETNX + 硬 TTL + Lua 安全释放);锁粒度到业务键,持有时间 ≤ 30s
- **[注意]** 内存/降级模式下锁退化为进程内信号量(分片近似,不同键可能互相排斥)——严格互斥场景必须 Redis 模式并监控降级告警
- **[禁止]** 用数据库行锁模拟分布式锁;锁内不做慢操作(锁内只做"检查 + 标记",重活出锁后干)
