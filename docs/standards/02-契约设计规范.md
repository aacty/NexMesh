# 02 契约设计规范(API / DTO / 分页)

## 路由

- **[强制]** 资源复数、kebab-case:`/api/orders`、`/api/medical-records`
- **[强制]** 层级不超过两层:`/api/orders/{id}/items` 封顶;更深的关系用查询参数或独立资源
- **[强制]** 路由参数带约束:`{id:guid}` / `{id:long}`
- **[禁止]** 动词进路由(用 HTTP 方法表达:`POST /api/orders` 而非 `/api/createOrder`)

## DTO

- **[强制]** DTO 用 `record`,只含对外字段;**实体直出即事故**(软删除/审计字段、内部外键都会漏出去)
- **[强制]** 时间一律 UTC ISO8601(`DateTime.UtcNow`,ApiResult 序列化带 Z);金额用 `decimal`
- **[强制]** 枚举序列化为字符串(名称),禁止魔数下发给前端
- **[建议]** 命名:请求 `XxxRequest`,响应 `XxxDto`/`XxxResponse`,事件 `XxxCreated/Changed/Removed`(过去式)

## 统一响应

- **[强制]** 错误响应由框架保证(`ApiResult` 格式);成功响应**建议**包 `ApiResult<T>.Ok(data)`,纯查询也可裸返——一个服务内保持一致
- **[强制]** 分页响应用 `PagedResult<T>`(Items/TotalCount/PageIndex/PageSize/TotalPages,禁止裸数组 + 头部传总数的私有约定

## 分页与排序(标准四参数)

```csharp
public sealed record ListOrdersRequest(int Page = 1, int PageSize = 20, string? SortBy = null, bool Desc = false);
```

- **[强制]** `PageSize` 由 `ToPagedResultAsync` 钳制(≤500),不得自行实现分页绕过上限
- **[强制]** `SortBy` 必须走 `OrderByWhitelist`,白名单在端点内显式声明
- **[建议]** 新契约从 v1 起带版本意识:破坏性变更走新路由(`/api/v2/orders`)或新字段可空化,不悄悄改语义

## 幂等

- **[强制]** 创建类端点支持幂等键(请求头 `Idempotency-Key` 或业务唯一键);重复提交返回原结果或 409(409xx 错误码),禁止产生双数据
