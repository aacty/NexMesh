# 01 分层与架构规范

## 项目结构(默认两层,长到大再拆)

```
MyService/                  # 单项目 = Host + Features
├── Program.cs              # 唯一启动接线点,从上往下读
├── Features/               # 按业务垂直切片,一个功能一个文件
│   ├── Orders/
│   │   ├── Order.cs            # 实体
│   │   ├── OrderContracts.cs   # DTO + 事件
│   │   ├── CreateOrder.cs      # 端点:路由/校验/编排,一屏读完
│   │   └── NotifyOnOrderCreated.cs
│   └── Products/
└── appsettings.json
```

- **[强制]** 端点文件内只做:参数绑定 → 业务校验 → 编排调用 → 响应;禁止写 SQL 拼接、循环套库查(N+1)
- **[强制]** 业务逻辑超过一屏(约 40 行)时下沉到同目录 Service 类,端点保持"薄壳"
- **[强制]** `Features/*` 之间禁止互相引用类型;跨切片复用经 Core 层领域服务或事件
- **[建议]** 超过 ~15 个切片或多人同改一个项目时,拆 `MyService.Core`(实体/领域)+ `MyService`(Host)

## Program.cs 接线

- **[强制]** 只用 NexMesh 的 `AddNexMesh*` / `Use*` / `Map*` 显式方法,每行注明来源包(参考 ReferenceService)
- **[强制]** 中间件顺序:`UseNexMeshTraceId` → `UseNexMeshExceptionHandling` → 认证 → 授权 → `UseFastEndpoints` → 端点映射
- **[禁止]** 在 Program.cs 写业务分支(if 判断环境连不同库用配置表达,不用代码)

## 依赖方向

```
Program.cs → Features/* → NexMesh.* 包 → 第三方(FreeSql/CAP/...)
                     ↘ NexMesh.Core(共享抽象,人人可依赖)
```

- **[强制]** 实体实现 `ISoftDelete`/`IAudited` 只依赖 NexMesh.Core,不带 FreeSql 特性;确需表特性(如 `[Column]`)时集中在实体并注释原因
