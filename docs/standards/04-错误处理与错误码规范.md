# 04 错误处理与错误码规范

## 异常分类(只有两类)

| 类型 | 抛法 | 框架行为 |
|---|---|---|
| 业务异常 | `throw new MeshException(msg, errorCode, statusCode)` | 按 StatusCode 返回,消息原文给调用方,不打 Error 级日志 |
| 程序缺陷 | 任何其他异常 | 500 + "服务器内部错误",消息**不泄露**,Error 日志带堆栈 |

- **[强制]** 业务失败用异常表达,不返回 `(bool ok, T data)` 这类私有约定——统一由 `ApiResult` 承载
- **[强制]** 未知异常禁止 `catch` 后吞掉或改写再抛;需要补偿清理时 catch 后 `throw;`(保留堆栈)
- **[禁止]** 在循环里 catch 全部异常继续跑(把数据问题变成静默脏数据)

## 错误码段位(5 位,HTTP 对齐前缀)

| 段 | 含义 | 示例 |
|---|---|---|
| 400xx | 请求/参数问题 | 40001 参数格式、40002 业务校验、40010 非法排序字段 |
| 401xx | 未认证 | 40101 token 无效/过期 |
| 403xx | 已认证无权限 | 40301 角色不足 |
| 404xx | 资源不存在 | 40401(框架保留:通用不存在)40402 起服务自定义资源细分 |
| 409xx | 冲突 | 40901 重复提交、40902 状态冲突 |
| 5xxxx | 内部错误 | 500(框架固定) |

- **[强制]** 每个服务维护 `docs/errorcodes.md` 登记表:码 → 含义 → 抛出位置;PR 引入新码必须同步登记
- **[强制]** 错误码一旦发布不可改语义,废弃标注 superseded-by
- **[建议]** `statusCode` 缺省 400;业务语义明确时给准确值(不存在→404,冲突→409)

## 开发调试

- `NexMesh:ExposeInternalErrors=true` 仅限 Development(见配置规范);**[强制]** 生产禁开
