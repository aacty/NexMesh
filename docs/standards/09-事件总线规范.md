# 09 事件总线规范

## 事件设计

- **[强制]** 事件是不可变 record,过去式命名,只含数据 + 语义完整的字段:

```csharp
public sealed record OrderCreated(Guid OrderId, string CustomerName, decimal Amount);
```

- **[强制]** 事件自包含:消费方拿到即能处理,**[禁止]** 只发 Id 让消费者回查再算(强耦合;确需回查注明容错)
- **[建议]** 事件版本演进只加字段(可空/默认值);破坏性变更发新事件名 `OrderCreatedV2`

## 发布

- **[强制]** 事务提交后发布;事务内发布 = 崩溃丢事件(Memory 模式)或脏事件
- **[强制]** 跨服务发布走 RabbitMQ(CAP Outbox 保事务一致);Memory 仅单服务内解耦
- **[禁止]** 发布方依赖订阅方的处理结果(事件是通知,不是 RPC;要结果就直调)

## 订阅(Memory 模式)

```csharp
public sealed class NotifyOnOrderCreated : INexMeshEventHandler<OrderCreated> { ... }
builder.Services.AddNexMeshEventHandler<OrderCreated, NotifyOnOrderCreated>();
```

- **[强制]** 处理器幂等(重复派发不双写);框架保证单处理器异常不影响其他处理器,但**[禁止]** 依赖该顺序写业务
- **[强制]** 处理器内不再同步发布新事件(链式反应改为各自订阅原始事件)
- **[建议]** 处理慢的动作用后台任务接手,事件处理器只落"待办"

## 订阅(RabbitMQ 模式)

- 消费类标 `[CapSubscribe("OrderCreated")]`(事件名=类名);重试由 CAP 配置,消费失败记日志 + 告警,不无限重试
